অ্যাপ বা ওয়েবসাইট বানাতে গিয়ে **API Error** দেখোনি, এমন ডেভেলপার খুঁজে পাওয়া কঠিন। API key বসালে, কোড চালালে — আর স্ক্রিনে লাল অক্ষরে `401` বা `429`। এই পোস্টে সবচেয়ে কমন API error-গুলোর মানে, কারণ আর **ধাপে ধাপে সমাধান** দিলাম — পড়া শেষে আর গুগলে ঘুরতে হবে না।

## Error Code চিটশিট

| কোড | মানে | সবচেয়ে কমন কারণ |
|------|------|------------------|
| 401 | Unauthorized | ভুল বা মেয়াদোত্তীর্ণ API key |
| 403 | Forbidden | key ঠিক, কিন্তু অনুমতি (scope) নেই |
| 404 | Not Found | ভুল URL / endpoint |
| 429 | Too Many Requests | লিমিট শেষ — বেশি request পাঠিয়েছো |
| 500 / 503 | Server Error | ওদের সার্ভার ডাউন বা ব্যস্ত |

## 401 Unauthorized — key-তেই সমস্যা

সবচেয়ে কমন error। এর মানে সার্ভার তোমার key চিনতে পারেনি।

![401 Unauthorized error — ভুল API key](/images/api-401-error.webp)

**সমাধান:**
1. key-টা পুরো কপি হয়েছে কিনা দেখো — শুরু বা শেষে space/নতুন লাইন ঢুকে যায় প্রায়ই।
2. key মেয়াদোত্তীর্ণ বা revoke হয়ে গেছে কিনা চেক করো — নতুন key বানিয়ে দেখো।
3. key ঠিক জায়গায় পাঠাচ্ছো কিনা দেখো — header-এ `Authorization: Bearer <key>` নাকি অন্য ফরম্যাট চায়, ডকুমেন্টেশন মিলিয়ে নাও।

## 429 Too Many Requests — লিমিট শেষ

এর মানে তুমি নির্দিষ্ট সময়ে অনুমতির চেয়ে বেশি request পাঠিয়ে ফেলেছো। ফ্রি প্ল্যানে এটা খুব কমন।

![429 Too Many Requests — rate limit](/images/api-429-ratelimit.webp)

**সমাধান:**
1. **অপেক্ষা করো** — লিমিট সাধারণত মিনিট/ঘণ্টা/দিন পরে রিসেট হয়।
2. request-এর মাঝে বিরতি (delay) দাও — লুপে একসাথে শত শত কল পাঠিও না।
3. একই কাজ কম request-এ করা যায় কিনা দেখো (caching, batch request)।

## নতুন API version এলে পুরনো কোড ভাঙে

এটা আমার নিজের অভিজ্ঞতা — একটা API-এর **নতুন version/model** এলে পুরনো endpoint বন্ধ হয়ে যায়, আর সব ওয়েবসাইটে নতুন API দিলেও কাজ হয় না। যেমন Gemini-তে মডেলের নাম বদলে গেলে পুরনো কোডে `404` আসে।

**সমাধান:**
1. প্রোভাইডারের **changelog/migration guide** পড়ো — কী বদলেছে, সেটাই আসল উত্তর।
2. endpoint URL আর মডেল/প্যারামিটারের নাম নতুন ডকুমেন্টেশনের সাথে মিলিয়ে নাও।
3. একটা **ছোট test request** দিয়ে যাচাই করো, তারপর পুরো কোড বদলাও।

## ডিবাগ করার সঠিক ক্রম

যেকোনো API error-এ এই ক্রমে এগোও — ৯০% সমস্যা প্রথম তিন ধাপেই ধরা পড়ে।

![API error ডিবাগ ফ্লোচার্ট](/images/api-debug-flowchart.webp)

1. **Error code পড়ো** — সংখ্যাটাই বলে দিচ্ছে সমস্যা কোন দিকে।
2. **Key যাচাই করো** — পুরো কপি, মেয়াদ, সঠিক header।
3. **Endpoint মিলাও** — URL, method (GET/POST), প্যারামিটার।
4. **Quota দেখো** — ড্যাশবোর্ডে লিমিট শেষ কিনা।
5. **সার্ভার স্ট্যাটাস** — ওদের status page-এ outage আছে কিনা দেখো।

## সাধারণ প্রশ্ন

**API key কোথায় রাখবো?**
কোডে সরাসরি (hardcode) কখনো নয় — environment variable বা secure vault-এ রাখো। GitHub-এ key পুশ হয়ে গেলে সাথে সাথে revoke করে নতুন বানাও।

**429 এলে কতক্ষণ অপেক্ষা করবো?**
Response header-এ `Retry-After` থাকলে সেটা মানো। না থাকলে ১ মিনিট অপেক্ষা করে আবার চেষ্টা করো, প্রতিবার দ্বিগুণ বিরতি দিয়ে (exponential backoff)।

**নতুন API version-এ migrate করবো কীভাবে?**
আগে ডকুমেন্টেশনের migration guide পড়ো, একটা আলাদা test প্রজেক্টে যাচাই করো, তারপর মূল প্রজেক্টে বদলাও।
